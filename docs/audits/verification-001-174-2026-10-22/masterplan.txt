0. PROJEKTZIEL

Kurvenfunk wird ein modernes österreichisches Fußballportal mit News, Sportdaten,
Community und Forum.

Der Schwerpunkt liegt nicht nur auf klassischen Fußballnachrichten, sondern auf
einer starken Community rund um Vereine, Spiele und aktuelle Themen.

Kurvenfunk soll dabei:

   ●​   schnell sein

   ●​   modular aufgebaut sein

   ●​   einfach wartbar sein

   ●​   automatisierte Newsimporte ermöglichen

   ●​   automatisierte Sportdatenimporte ermöglichen

   ●​   starke Moderationswerkzeuge besitzen

   ●​   Vereinsfans personalisierte Inhalte zeigen

   ●​   datenschutzbewusst aufgebaut sein

   ●​   später auf weitere Wettbewerbe und Länder erweitert werden können

12. USER ROLE & ACCOUNT STATUS MODEL

Rollen und Accountstatus werden getrennt behandelt.

Rollen

USER

TRUSTED_USER

MODERATOR

EDITOR

ADMIN

SUPERADMIN

Bedeutung

USER

Normaler registrierter Benutzer.

TRUSTED_USER

Vertrauenswürdiger Benutzer; später eventuell weniger Spamlimits oder zusätzliche
Communityrechte.

MODERATOR

Kann Communityinhalte moderieren.

EDITOR

Kann redaktionelle Inhalte verwalten.

ADMIN
Kann große Teile der Plattform administrieren.

SUPERADMIN

Technische und vollständige administrative Rechte.



Accountstatus

ACTIVE

LIMITED

BANNED

ACTIVE

Normaler Zustand.

Darf entsprechend seiner Rolle alle erlaubten Funktionen verwenden.

LIMITED

Benutzer darf weiterhin:

   ●​   Portal lesen

   ●​   News lesen

   ●​   Spiele ansehen

   ●​   Forum lesen

   ●​   voten/reagieren

Benutzer darf nicht:

   ●​   Kommentare erstellen

   ●​   auf Kommentare antworten

   ●​   Threads erstellen

   ●​   Forum Posts erstellen

Optional können einzelne Rechte später granular eingeschränkt werden.

BANNED

Account ist vollständig gesperrt.

Der Benutzer darf:

   ●​   keine authentifizierten Aktionen durchführen
   ●​    keine Communityfunktionen verwenden

Sessions werden widerrufen.

Login kann blockiert bzw. auf eine Sperrinformation umgeleitet werden.



13. YELLOW / RED CARD SYSTEM

Moderation verwendet ein Fußball-inspiriertes Kartensystem.

Gelbe Karte

Eine gelbe Karte stellt eine formelle Verwarnung dar.

Speichern:

userId

moderatorId

reason

description

relatedContentId

createdAt

expiresAt optional

Regel

Standard:

1 Gelbe Karte → Verwarnung

2 Gelbe Karten → deutliche Warnung

3 Gelbe Karten → automatisch Rote Karte



Rote Karte

Rote Karte bedeutet:

AccountStatus = BANNED

Eine rote Karte kann entstehen durch:

3x Gelb

oder direkt bei einem schweren Verstoß.
Beispiele für mögliche direkte rote Karte:

   ●​   massive Drohungen

   ●​   schwerer Missbrauch

   ●​   gezielte Veröffentlichung privater Daten

   ●​   automatisierter Spam/Bot-Angriff

   ●​   bewusste Umgehung bestehender Sperren

Die tatsächlichen Moderationsregeln werden später in den Community Guidelines
festgelegt.



LIMITED Status

Zusätzlich zum Kartensystem kann ein Moderator den Benutzer temporär auf:

LIMITED

setzen.

Beispielsweise:

24 Stunden

3 Tage

7 Tage

30 Tage

Danach wird der Status automatisch wieder auf ACTIVE gesetzt, sofern keine
andere Sanktion aktiv ist.



14. IP PROTECTION MODEL

IP-Sperren werden nicht als einziges Identifikationsmittel verwendet.

Sie ergänzen Account- und Session-Sperren.

Speichern

Wenn möglich:

HMAC(IP + secret)

anstatt dauerhaft Klartext-IP zu speichern.

Einsatz
IP-basierte Schutzmaßnahmen für:

    ●​   Registrierung

    ●​   Login

    ●​   Password Reset

    ●​   Kommentare

    ●​   Forum Posts

    ●​   Reports

    ●​   Sperrumgehung

    ●​   Bots

    ●​   Spam

Sperrtypen

Rate Limit

Temporary IP Block

Extended IP Block

Manual IP Ban

Bei roter Karte

Optional:

Account Banned

+

Sessions revoked

+

bekannte IP Hashes temporär blockiert

IP-Sperren müssen wegen Shared IPs, Mobilfunk, VPN usw. vorsichtig eingesetzt
werden.
